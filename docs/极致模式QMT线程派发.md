# 极致模式 QMT 线程派发

2026-10-14，入口版本 `lite_20261014_03`。

极致模式的普通桥此前由接收线程入队，再唤醒独立工作线程执行 QMT API。现在与通用模式主入口保持一致：接收线程只入队，由 QMT 的定时器和 `handlebar` 回调消费请求。复用入口定时器，默认间隔为 1 ms，可在网页绑定中独立配置；不再为普通桥额外注册 500 ms 定时器，也不启动普通桥工作线程。没有行情回调时，定时器仍可处理请求。

定时器和 `handlebar` 会更新两个桥的 `ContextInfo`。普通桥仍用 `dispatch_lock` 串行执行请求，保留查询合并、每轮数量/时间限制、行情耗时统计和现有数据编码协议。普通、上海、深圳三份极致模板均已同步，继续采用 GBK、CRLF 和 Python 3.6 兼容语法，不依赖外部 `cfquant` 包。

同步 `xttrader.order_stock` 经交易通道进入后，转入普通桥。提交订单时保留 RPC 等待状态，但立即把控制权交还 QMT；匹配的订单回调到达后，在后续派发中返回结果。这样不会在 QMT 线程内等待由同一线程产生的回调。订单身份匹配、超时清理、失败回复沿用通用模式，确认超时不自动重复下单。

## 部署验证

更新并重新部署极致策略、重启该策略后，检查普通桥状态：

| 字段 | 新版本预期值 |
| --- | --- |
| `qmt_runtime_entry_version` | `lite_20261014_03` |
| `dispatch_on_qmt_thread` | `true` |
| `dispatch_thread` | `qmt_caller_thread` |
| `worker_thread_alive` | `false` |
| `schedule_timer` | `false`（普通桥独立定时器关闭） |
| `ctype_trade_timer_interval_ms` | 默认 `1`，配置后显示绑定所选值 |
| `log_enabled` | 当前绑定实际使用的日志开关 |
| `ctype_trade_route_mode` | `xttrader_to_normal_qmt_timer` |

接收线程仍会存在；它们负责通信，不代表业务请求仍在后台线程执行。仅更新磁盘上的模板不会改变已经运行的策略。

部署后的速度需要实测：在相同交易时段、参数、数据量和日志开关下，交替调用两种模式，分别比较页面总耗时、QMT 排队、原生取数、转换、编码耗时。此次消除了线程执行路径的差异，但定时器调度、QMT 版本、行情缓存和终端负载仍会影响结果，不能承诺消除全部 10–40 ms 差距。与通用模式一样，耗时较大的单次取数或结果编码会占用 QMT 回调线程；每轮时间限制不会中断正在执行的请求。

## 网页绑定设置

“绑定 → 添加 / 编辑 → 调度与日志”适用于通用、极致模式。间隔为 1–1000 ms 的整数，默认 1 ms，优先降低调度等待。已保存的独立间隔继续保留，也可按终端负载选择 5、10、20、30 ms 等值。实际触发精度和接口总延迟仍取决于 QMT、系统负载及订单回报。

日志可选关闭、开启、跟随全局。新建绑定的表单默认关闭，旧绑定未独立配置时继续跟随全局。此开关控制 cfquant 桥及通信端在 QMT 中的常规日志，不关闭 QMT 客户端自身提示、Python 异常或外部 Web / PipeHub 日志。关闭时不构造原始订单回调的日志摘要。各绑定的策略使用自己的开关，避免同一 Python 进程中的全局日志缓存覆盖绑定设置。

配置保存在账号的 `qmt_runtime` 中，例如 `{"timer_interval_ms": 5, "log_enabled": false}`；`log_enabled: null` 表示跟随全局。接口局部修改或旧客户端省略该字段时保留已存值。生成的普通、SH、SZ 策略包嵌入实际间隔和日志开关，优先于旧环境变量。

修改使用现有绑定保存和策略同步流程。运行中的旧策略不会热切换间隔，须按部署提示重新启动策略或 QMT。升级 Web 后端后再保存；前端会检查返回值，避免旧后端忽略新字段却显示保存成功。

## 维护与测试

`tools/sync_qmt_dispatch.py` 从通用桥及主入口同步派发实现，仅去除极致模式不包含的磁盘订单元数据逻辑。`sync_qmt_fileless.py` 在生成流程末尾应用该同步，批量接口和兼容接口的再生成也会保留新的派发方式。

`cfquant/tests/test_lite_qmt_dispatch.py` 加载三份模板的实际桥类和回调函数，以模拟 QMT 和通信验证线程归属、定时器、ContextInfo 更新、DataFrame 兼容、查询合并、交易转发、订单回调匹配和失败不重复提交。测试不连接真实交易终端。部署路径测试另行检查实际策略包采用更新后的模板。

可用 `python tools/sync_qmt_dispatch.py --check` 检查派发代码是否与通用模式来源一致。
