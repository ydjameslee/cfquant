# 沪港通、深港通扩展方案

## 目标与范围

在西南证券大 QMT + ctypes 模式中，让同一资金账号下的 STOCK、HUGANGTONG、SHENGANGTONG 分别完成资产、持仓、委托、成交查询，以及限价买卖、撤单和回报订阅。先完成 cfquant，FutuTrader 后续接入。现有普通账户部署需要保持兼容。

第一版建议支持明确价格、明确股数的普通买卖。竞价、碎股特殊委托、算法单和自动换汇不纳入首版。真实下单验收需要用户单独指定交易，开发与自动验证不得发送真实订单或撤单。

用户已明确：FutuTrader 留到之后实现。本轮不修改 FutuTrader 的代码、trader.json 或接入配置，也不将其接入列为本轮验收条件；当前交付边界为 cfquant 自身的网页、SDK、QMT 桥接及部署。

## 已核实的现状

- 当前本地 dev 基于 4e03056（0.2.42）。SDK 已定义港股通账户常量 7、11；桥接查询已有部分类型转换。
- Web 的 normalize_account_type 拒绝两个港股通类型，前端缺少选项。
- Web 的 normalize_stock_code 不支持 HK；裸五位代码会按 A 股推断并补成六位。
- account_routing 和 normal_bridge 的部分账户类型转换缺少 7、11，可能导致订阅与回报身份不一致。
- 自动部署策略名称只含资金账号、模式和角色；三种同号账户会冲突。QMT 账户绑定筛选和校验也没有完整覆盖港股通。
- passorder 调用没有单独的 account_type 参数；不能仅在请求中添加该字段就宣称正确区分沪港通、深港通。

## 方案比较

1. **推荐：沿用现有桥接，按账户类型隔离逻辑账户与托管策略。** 改动与现有部署结构一致；需要补齐部署身份、QMT 绑定和回报归属。
2. 单一策略管理所有账户类型。策略数量少，但涉及更大的上下文、回报和路由改造；现有按账户部署模式不宜直接改成这一方案。
3. 仅补网页类型和常量。无法解决代码格式、策略冲突和实际下单通道选择，不作为完整交付方案。

## 设计

### 身份与部署

统一账户类型转换，包括 7/11、标准字符串和明确的别名。内部身份沿用 `(bridge_id, account_type, account_id)`；缓存、请求、订单关联、订阅均保留类型。

新增港股通策略名称包含类型；已有 STOCK 策略名称保持兼容。部署计划按 QMT 根目录、账号、类型、模式、角色区分资源，核查共享配置文件和互斥规则，防止后部署的账户覆盖前一个。绑定只接受与账户类型一致的 QMT 账户 Key。

### 查询与订单

Web 增加两个账户类型和完整查询入口。港股代码保留五位和前导零，明确区分证券所属市场与沪/深港通交易通道；具体传入 QMT 的代码以本机合约信息和官方接口约定核实后固定。

首版支持限价买卖、按股数下单和对应账户撤单。官方文档说明买卖操作号 23/24 覆盖港股通，但这一事实不足以区分同号账户的两个通道。必须验证 QMT 策略绑定、上下文和合约代码如何共同决定通道，禁止默认回退到 STOCK 或另一个港股通账户。

报价、数量和金额字段明确单位；数量校验采用标的自身交易单位，不套用 A 股固定手数。资金返回字段保留原始币种信息，未经确认不将人民币资金与港币价格直接计算为可买数量。

### 回报与异常

优先使用 QMT 原始账户类型与可靠订单关联信息确定回报归属。无法唯一归属的回报标记为无法识别并记录，不按最后一次请求的类型分发。同步、异步下单错误和撤单结果也必须保留账户类型。

网页展示选定通道，订单确认信息包含账户类型。连接失败、未绑定、查询失败和空持仓分别表示，避免把失败展示为无资产。

## 验证与交付顺序

1. 只读核查本机沪、深港通账户授权绑定及 QMT 原始字段，确认同号账户的下单通道选择依据。没有可信依据时，交易入口保持不可用并报告具体缺口。
2. 完成统一身份、部署隔离、Web 配置和查询；分别验证三种账户数据。
3. 完成代码转换、限价订单参数、撤单与回报关联。使用替身 passorder/cancel 验证参数，不触达真实交易。
4. 回归同号三账户隔离、数值/字符串账户类型、缺少类型的回报、五位港股代码、错误账户/市场组合、重复部署及旧配置兼容。
5. 输出部署备份及回滚说明。需要重启 QMT 时统一安排；登录由用户完成。真实交易验证单独进行，不把模拟调用通过视为真实成交验证。

用户已确认实施。查询、交易参数、网页配置、类型隔离及部署代码已实现；本机普通、沪港通、深港通三个策略均为 running，各自的资产、持仓、委托、成交共 12 项强制刷新只读查询全部成功。未进行真实下单或撤单验证。部署中发现原普通模型控制路径迁移问题，已恢复旧路径并补充回归测试，重新登录后验证恢复。

最终相关回归集 150 项通过，前端 JavaScript 语法检查通过。全仓库测试未全绿：原有 test_cftrader.py 的 test_single_cancel_async_returns_seq_and_deduplicates_callback 和 test_single_cancel_sysid_async_preserves_sysid_and_deduplicates_callback 在多个传输模式下存在委托号类型/字段预期不一致；本次全库检查达到 10 个失败后停止（124 passed、5 skipped），首次失败在开发基线中也已复现。相关回归集通过不代表全仓库测试通过。
