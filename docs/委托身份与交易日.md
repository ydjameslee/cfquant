# 委托身份与交易日

内部编号的匹配范围为：桥接实例、账户类型、资金账号、QMT 返回的交易日、内部编号。这个组合仍可能出现多个候选，程序必须检查唯一性，不能选第一条。

`trading_day` 与 `order_date` 分别保存。午夜、周末和夜间预约委托都不能用电脑当天日期推算交易日；只有委托日期时，交易日保持未知。历史版本自动生成的 `trade_day` 不作为权威交易日使用。

完整委托编号、内部 `m_nRef`、柜台合同号是不同编号空间。它们的字符串碰巧相同，不代表是同一委托。查询和回报保留原始字段，不用完整编号填充缺失的内部编号。

回报去重只有在账户及权威交易日明确时才执行终态过滤，避免前一交易日的已成交状态吞掉下一交易日的部分成交回报。元数据不再按电脑时间在 09:00、16:00 清空。

SDK 的 `query_stock_order` 支持可选 `trading_day`，同编号有多条候选时抛出歧义错误。`cancel_order_stock` 和异步版本支持可选 `trading_day`、`order_id_kind`；`order_id_kind="internal"` 表示输入为内部编号，必须用权威交易日核对到唯一的 QMT 委托。网页 `/api/cancel` 同样转发这两个字段。

默认 `order_id_kind="auto"` 会查询并核对编号；查询不到目标不会继续撤单。显式 `native` / `sysid` 表示调用方提供的就是原生柜台编号，只在缺少查询能力且未指定交易日时保留原有直传兼容路径；这不适用于内部编号。指定日期时即使是柜台编号也必须核对，日期无效、冲突或无法查询均报错。

SDK 不再仅凭股票代码和备注合成异步下单成功回报。缺少权威交易日或内部编号时，等待原生带 `seq` 的异步响应；不能把历史委托的回报关联到新请求。网页仅在委托身份明确时合并回报，按行撤单会转发查询所得的交易日。

通用 ctypes 桥和共用 `TxTradeBridge` 的交易桥，在调用 `passorder` 前登记每笔请求的唯一策略标记。提交请求时尚未取得 QMT 内部编号或交易日是正常情况；只有 QMT 原样返回已登记标记，且桥接实例、账户类型、账号一致，并返回有效交易日和原始 `m_nRef`，桥接才将该身份绑定到唯一待处理请求并生成 `seq` 回报。股票代码、用户备注和队列顺序均不能代替这个关联依据。异步确认只表示已定位委托，不代表成交。

唯一标记属于桥接内部信息。普通委托、成交查询和回报应将已登记标记还原为原始策略名；错误回报消费其处理上下文后也不能丢失公开字段的还原能力。陌生或仅形似内部标记的手工策略名不应被截断。映射采用当前进程内的有界缓存；进程重启或缓存淘汰后，无法证明归属的旧标记保持原样，不按后缀猜测，也不关联到新请求。旧的独立 LITE 脚本和 `CfquantQmtBridge` 不是这套实现，不能由这些测试推断已具备相同保证。

这里的交易日只用于本地核对，不作为新增参数传给 QMT 原生 `cancel`。[QMT 官方撤单文档](https://dict.thinktrader.net/innerApi/trading_function.html) 的示例说明通过查询得到的 `m_strOrderSysID` 定位原生撤单；内部编号不能直接替代它。柜台委托号为空的废单不能靠内部编号拼出可撤目标。柜台受理、撤单完成仍应分别由原生返回及后续回报确认。

测试全部使用离线对象与模拟原生函数，不提交真实委托或撤单。没有权威交易日的现有废单不能用于证明跨交易日撤单已通过实盘验证。
