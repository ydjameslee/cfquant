# 行情结果编码优化（极致模式首轮验证）

## 解决的问题

旧行情接口回退到扩展接口后，兼容层按字段生成股票×日期的 DataFrame。一只股票、5668 个日期、5 个字段会形成 5 张 1×5668 的宽表。原编码器使用 `itertuples`，会逐列建立 pandas 对象，且为每列重复格式化 dtype 名称；这些成本会占用 QMT 请求处理线程。

本次保留原有接口返回布局和协议版本，优化 DataFrame 的取值与类型判断过程：

- 先通过 `astype(object, copy=False)` 保留各单元格类型，再批量获取行数据，避免整数/浮点混合矩阵将大整数舍入。
- 每种 dtype 仅判断一次是否需要按对象列还原。
- 保留已有逐单元格编码规则，以及列名、索引、索引名称和对象列标记。
- 使用 pandas 0.22 已有的 API，不依赖新版 `to_numpy`。
- 同步主极致入口及独立沪市、深市入口，避免单文件副本与共享源码出现差异。

兼容测试同时发现并修复了两个既有协议问题：数据正文中的 `|` 不应被当作 LTtx 通道前缀；结构化 ndarray 的记录经 JSON 变成列表后，需要恢复为元组再交给 NumPy，否则含对象深度字段的 Level2 数据无法还原。

## 返回结构约束

本次不通过缩短历史、减少字段、替换接口或转置公开返回值来提速。

- 旧接口兼容结果仍为 `字段 → DataFrame`，DataFrame 的行是股票、列是日期。
- 扩展接口仍为 `股票 → DataFrame`，DataFrame 的行是日期、列是字段。
- 原生旧接口成功时保留原生结果原有布局，不强制改成另一种形状。
- SDK 仍还原 DataFrame、ndarray 等对象；HTTP 仍使用既有 JSON 表示。
- int64、uint64 大整数、可空整数、对象列、深度数组、重复标签、元组标签、空表和非有限数值均有回归覆盖。

这里的兼容性结论针对现有协议行为和覆盖的行情数据契约，不代表新增支持所有 pandas 扩展 dtype 或元数据。大整数在 Python SDK/JSON 文本中保持精确；浏览器 JavaScript Number 的精度限制不是本次修改的范围。

## 其他数据接口的共用转换

共用 `pack_response` / `pack_event` 会递归调用 `encode_value`。因此上述 DataFrame 编码优化已经覆盖返回表格的行情、本地历史、财务、原始财务、复权因子等接口，包括嵌套在股票和财务表字典中的 DataFrame。它并不是某一个 HTTP 接口专用的优化。

进一步审计发现，Web 输出与订阅/Level2 的记录转换发生在独立路径中，不能仅靠协议编码器提速。本轮增加 `dataframe_numeric_rows`，供这些路径共用：

| 返回路径 | 处理方式 |
| --- | --- |
| SDK/RPC 中的 DataFrame | 使用上一轮批量编码，保留表格协议与 SDK 还原结构 |
| Web 的数值 DataFrame → JSON | 批量取得原值，直接构造既有索引→字段映射，复用列名转换 |
| 行情订阅、部分 Level2 的数值 DataFrame → 记录列表 | 批量取得原值，维持记录列表和字段顺序 |
| ndarray、Series | 既有编码已使用批量 `tolist`，不涉及宽表逐列建立 Series 的问题 |
| full_tick、证券信息、板块、交易日期等字典/列表 | 继续递归处理原有结构，没有 DataFrame 列对象创建成本 |

新共用取值路径只接受普通 NumPy 数值/布尔列，先转 object 再合并。时间、可空扩展类型、对象列、重复列和零列等情况继续使用 pandas 原有转换规则，保留空值、时间表达、警告与异常语义。Web 的重复索引错误和递归深度限制保持原有行为；订阅记录继续保留重复时间戳，不会按索引去重。

### 补充回放结果

各测 5 次取中位数。行情输入为相同的真实捕获值；财务表是用于验证嵌套结构的合成样本。

| 转换 | 环境 | 优化前 | 优化后 |
| --- | --- | ---: | ---: |
| Web 行情宽表，5 张 1×5668 | Python 3.12 / pandas 2.3.3 | 1053.170 ms | 29.858 ms |
| Web 行情表，5668×5 | 同上 | 29.255 ms | 13.707 ms |
| Web 嵌套财务表，2×300 | 同上 | 9.211 ms | 0.620 ms |
| QMT 数值记录，5668×5 | Python 3.6 / pandas 0.22 | 89.901 ms | 31.475 ms |

所有 Web 回放结果的 JSON 文本（包括字段顺序和数值类型）与原实现相同。

QMT 老 pandas 的 `to_dict('records')` 原本使用 `self.values`，混合整数和浮点数时会把整数列先转成浮点数。例如 `18446744073709551615` 会变成浮点近似值。新的数值记录转换按原始列值保留整数，所以这一路在旧 pandas 下会修复原有的数值类型/精度损失，不应将它描述为与旧的错误结果字节一致。返回的列表、字典、字段及记录顺序不变。对此使用各列原值作为独立对照，并在实际 QMT Python 环境检查。

验证结果：572 项通过，7 项按既有条件跳过；另外 QMT 老环境 36 项、外部新环境 40 项记录转换比较通过。新增测试为 `cfquant/tests/test_table_conversion.py`。回放明细为 `runtime/reports/shared_conversions_python6_20261014.json` 和 `runtime/reports/shared_conversions_python12_20261014.json`。

这些共用优化不消除原生查询、旧行情兼容布局重建、海量响应发送，以及复杂对象转换本身的成本。老 LTtx 独立键值存储工具 `tx.put_df` 的上传路径不属于当前数据查询与回调链路，本轮未改动。

线上启用需要重新加载 Web/SDK，并重新部署极致策略；本轮回放未重启在线服务，也没有将独立回放耗时作为线上总耗时。
