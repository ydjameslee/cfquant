# 程序退出与连接清理

`xtdata.run()` 和 `XtQuantTrader.run_forever()` 在退出时自动清理各自的连接；Ctrl+C 的 `KeyboardInterrupt` 继续交给用户程序处理。SDK 等待 RPC 响应时也会在中断后关闭该连接、唤醒等待请求，避免后台线程持续等待。

```python
from cfquant import xtdata

try:
    xtdata.run()
except KeyboardInterrupt:
    pass
```

自定义主循环仍建议用 `finally` 显式释放资源。直接使用 `txl` 时，可保留原来的队列读取方式；主线程的 `Q.get()` 会定期返回 Python 检查中断，有数据到达立即返回。

```python
try:
    while True:
        message = tx.Q.get()
        if message is None:  # 连接被其他线程关闭
            break
        handle_message(message)
except KeyboardInterrupt:
    pass
finally:
    tx.close()
```

`txl.close()` 可以重复调用，会唤醒发送和接收队列、关闭 Socket、结束心跳与重连等待，并在总时间预算内等待后台线程退出。默认线程等待预算为 1 秒，不再固定休眠 1 秒。日志在预算内尽量写完；后台通信线程设为守护线程，进程正常结束时还有退出清理作为兜底。

完全关闭的 `txl` 实例不再重新连接；如需恢复通信，请创建新的实例。只关闭某个连接的 `close_tx()` / `close_tx_plus()` 仍可随后重新开启该连接。SDK 的 RPC 客户端可通过后续正常调用建立新的底层连接。

`xtdata.run()` 已关闭连接后，再调用 `unsubscribe_quote()` 会清理本地回调并返回 `False`，表示没有向服务端确认退订，不会为了退出清理重新建立连接。`XtQuantTrader.stop()` 同样跳过已经关闭的 RPC 连接上的退订请求。

关闭客户端不等于撤销已送达 QMT 的订单，也不保证尚未发送的队列全部发出。中断下单等待后，应查询订单状态确认结果，不要因中断自动重复下单。

验证使用假 Socket 和隔离 Python 子进程，覆盖空闲发送队列、网络接收、连接握手、心跳等待、重复关闭、正常进程退出、队列/RPC 中断及两个 SDK 常驻入口。用户自己创建的线程、无限阻塞的用户回调仍需由用户程序负责结束。
