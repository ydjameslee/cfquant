# 全推内部延迟诊断

更新 SDK、Web 服务和 QMT 极致模式入口脚本并重启对应策略后，在网页「接口 → 行情数据 → 内部延迟」填写市场或证券代码，发送请求获取订阅 ID，再点「连接推送」。网页和测试脚本默认订阅 `SH,SZ,BJ` 全市场，也可填写证券代码缩小范围。页面保留本批全部数据，默认每页 100 条，可选择 500 或 1000 条，支持翻页、代码筛选和延迟排序；不再截取前 80 条。每批数量以 QMT 实际回调为准，不要求每批包含市场内所有证券。停止推送、离开接口页面或关闭页面会释放诊断订阅；订阅后 8 秒内没有连接的订阅也会自动释放。

这是独立的原生全推订阅，采用独立的订阅号、事件和网页通道。普通 `xtdata.subscribe_whole_quote` 的回调数据保持不变。共享桥实现及三份极致模式入口均包含该功能；旧入口不支持此动作，需重新部署。测量时会增加一份订阅及编码开销，比较性能时应保持订阅范围与负载一致。

| 数值 | 测量范围 |
| --- | --- |
| 行情到 QMT | QMT 全推回调入口时间 − 原行情字段时间。表示本条行情进入 QMT 回调时已有的时间差，包含上游传递、回调前等待及行情本身未更新的时间。 |
| 行情到程序 | 接收端回调入口时间 − 原行情字段时间。包含行情源更新周期、券商/QMT 上游处理、cfquant 推送和接收调度。 |
| cfquant 内部 | 接收端回调入口时间 − QMT 发送前时间。包含结果编码、发送队列、通道传输、接收解码和回调排队。 |
| QMT 准备 | QMT 发送前时间 − QMT 全推回调入口时间。包含锁等待和准备元数据，结束于整批编码开始前。 |
| QMT 编码 | 直接编码路径下整批行情 JSON 序列化用时，以单调时钟测量。是 cfquant 内部延迟的一部分，不要重复相加；不包含外层通道封装。兼容回退或旧脚本没有该项时显示 `--`。 |
| 外部统计 | 外部 Python 接收回调之后，解析全部行情时间、计算延迟和汇总统计的用时。不计入上述接收延迟，也不含网页传输与渲染。 |

同一条行情满足：`行情到程序 ≈ 行情到 QMT + QMT 准备 + cfquant 内部`（各项保留三位小数，可能有舍入差）。`qmt_callback_at_ms` 在 QMT 回调的第一步记录，早于锁等待和数据转换；接收端用这个原始时间戳计算每只证券的 `qmt_quote_latency_ms`，不会用 Web 接收时间代替，也不会给 QMT 增加一次全市场延迟计算。首包等待订阅返回后才发送时，仍保留最初的回调入口时间。

行情到 QMT 的大值也可能是旧快照造成的，不能把它直接解释为 QMT 自身的执行耗时。缺少回调时间或行情时间时显示 `--`，负值保留。本次直接编码优化需要重新部署 QMT 入口；仅更新网页不能加快旧脚本的编码。

诊断推送和普通 `xtdata.subscribe_whole_quote` 均在 QMT 中优先用标准库 JSON 的 C 编码器直接序列化整批行情，省去 `quote_plain → encode_value → normalize_json_value` 对普通字典/列表的重复 Python 遍历。NumPy 标量和数组仅在编码器遇到时转换；NaN、Inf 或特殊对象回退到原兼容路径，仍保留原来的空值语义和字段结构。事件在协议元数据中带有纯 JSON 标记，外部 SDK 解析后也无需再次逐层解码 SDK 类型标签；Web 统一路由转发时同样保留该标记并使用直接编码。

普通全推用户回调仍收到 `{证券代码: 行情字典}`，不添加诊断字段、不拆分或合并批次，也不改变退订与回调顺序。单证券订阅及 Level2 接口沿用原编码方式。诊断接口的逐证券时间差和统计由外部 Python 执行，筛选、排序和分页由浏览器执行。跨进程发送仍必须编码和封装；本次优化减少遍历开销，尚未将同步管道写入改成独立发送队列，也没有改变 SDK 回调队列策略。

若 QMT 在原生订阅函数返回前同步发出首包，先编码并冻结该快照，待订阅成功后发送，避免原生复用数据对象导致内容变化。该等待计入 cfquant 内部；QMT 回调入口时间不会重置。

网页以 **Web 服务** 接收回调为终点，不含 WebSocket 到浏览器的传输和页面渲染。Python 脚本以 **该 Python 程序** 的诊断回调入口为终点；使用 Web 路由时包含额外转发环节。因此不同接收路径的数值不能直接当作相同链路比较。

时间戳使用本机 Unix 毫秒时间，保留小数不代表系统具备微秒精度。QMT 和接收端在不同机器时必须同步系统时钟；负值不会被截成零。行情时间字段按 `time / stime / timetag / datetime / updateTime / update_time` 依次尝试，支持秒、毫秒、微秒、纳秒 Unix 时间和完整中国时区日期时间。缺失或无法解析时显示 `--`，不会伪造零延迟。非交易时间的旧快照、长时间不成交证券会出现较大的「行情到程序」，应结合内部延迟判断。

行情到 QMT / 行情到程序的统计覆盖**当前整批有效时间**，显示有效条数，不随筛选或分页改变；内部延迟按批计算，网页保留最近 120 个已展示批次的内部延迟统计。Web 仅缓存最近 2 个完整批次，浏览器保留当前整批，不在表格中混入之前批次。悬停延迟可查看原始时间戳；连接时展示缓存最后一批并沿用真实接收时间。

「暂停刷新」固定当前展示批次，订阅继续接收，恢复时展示暂停期间收到的最新批次。暂停不会保存每一个中间批次。JSON 导出包含当前整批原始行情、每条延迟及批次元数据，不受筛选影响；CSV 导出包含当前筛选下所有匹配证券，不限当前页，`quote_json` 列保留该证券全部原始字段。CSV 采用 UTF-8 BOM。分页只限制 DOM 渲染数量，不截断接收与导出数据；全量传送到浏览器也会增加 WebSocket 流量和浏览器处理开销。

## Python 测试

编辑 `cfquant/tests/34_全推内部延迟测试.py` 顶部的 `BRIDGE_ID`、`TRANSPORT`、`MARKETS` 后运行：

```powershell
python -X utf8 "cfquant/tests/34_全推内部延迟测试.py"
```

脚本每秒打印本批实际接收标的数、打印条数、行情到 QMT / 行情到程序 / cfquant 内部的均值、P95、最大/最小值、最新价格、成交量、原始时间字段及 QMT/程序时间戳。行情时间统计覆盖当前整批，内部延迟统计为最近窗口；默认只打印 3 只的明细，可将 `SAMPLE_CODES = None` 改为打印全部，不影响整批统计。Ctrl+C 退订并关闭 SDK 连接。控制台输出放在主线程，避免阻塞接收回调。

也可使用 `cfquant.diagnostics.subscribe_whole_quote(code_list, callback)`，默认处理全部证券。回调报告的 `samples` 字段为完整逐证券明细，`summary` 为这些明细的汇总；显式设置 `sample_limit=N` 时只计算前 N 条明细及其统计。使用 `xtdata.unsubscribe_quote(id)` 退订。底层动作为 `xtdata.subscribe_whole_quote_latency`，原始事件外层为 `schema / qmt_callback_at_ms / qmt_push_at_ms / quotes`，直接编码路径另含 `qmt_encode_ms / qmt_encoding`，`quotes` 保留原始全推字段。

可运行 `python tools/benchmark_quote_latency_encoding.py --count 26475 --repeat 3` 比较诊断接口同一份合成行情在旧转换路径和直接编码路径下的耗时；增加 `--kind whole` 比较普通全推。该脚本不连接账户，只比较本机编码开销；真实 QMT 内嵌 Python、行情字段类型和负载可能不同，应部署后复测。

普通全推优化也需更新 QMT 侧桥代码并重启策略：极致模式重新部署对应的 `CFQUANT_LITE*.py`，通用模式更新 QMT 使用的共享桥代码。同步更新 SDK/Web 可省去接收端的重复解码；旧 SDK 仍能读取新事件中的标准 JSON 行情，只是不具备跳过额外遍历的优化。

HTTP：`POST /api/diagnostics/quotes/subscribe`、`POST /api/diagnostics/quotes/unsubscribe`、`GET /api/diagnostics/quotes/latest`、`GET /api/diagnostics/quotes/status`。WebSocket：`/ws/diagnostics/quotes?subscribe_id=...`。鉴权沿用现有 API/WebSocket 配置。
