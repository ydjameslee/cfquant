# QMT 组件登录工具

`tools/qmt_component_login.py` 根据绑定名称选择正在运行的 QMT，在其 GUI 线程上直接操作 Qt 密码组件并调用登录方法。它不使用模拟键盘、鼠标、坐标定位或剪贴板。

组件实现现已接入网页的自动启动与交易日重启服务，参见 [QMT 交易日自动重启与登录](QMT交易日自动重启与登录.md)。命令行工具本身仍不启动或退出 QMT；配置了登录账号时会核对或设置该账号。

## 当前验证范围

2026-10-19 最初的组件能力验证记录如下；当前登录策略已统一改为覆盖填写保存的凭据，下面的“保留已有密码”仅为历史能力验证：

| 终端 | 版本 | 验证结果 |
| --- | --- | --- |
| 国金模拟 | 2.1.19.200 | 前一轮直接赋值并调用登录方法成功；本轮通用工具可识别已经登录的状态。 |
| 华泰模拟 | 2.1.19.1 | 最小化状态下，保留密码框已有内容并直接调用登录成功。 |
| 华泰模拟 | 2.1.19.1 | 先清空密码框，通用工具检测为空后取得新密码、直接赋值并登录成功。 |

两个终端都使用 Qt 5.6.2 x64，并提供相同的相关导出方法。工具检查该 Qt 版本和进程位数，其他版本不会直接尝试套用内部结构。

华泰第一次已有密码测试已进入主界面，但早期结果检测在登录途中遇到暂时隐藏的密码框而报错，随后独立检查确认已经登录。该状态处理已修正，之后的空密码实测完整返回 `logged_in`、`attempts=["provided"]`、`minimized_before=true`、`script_errors=[]`。

当前强制重启、覆盖账号和密码、单次提交及旧任务隔离逻辑通过自动化测试验证。错误识别仅覆盖已定义的界面提示，密码被拒绝、未知提示和超时均不会自动连续重试。

## 使用

本机验证依赖：Python 环境中的 Frida 17.16.4、pywin32 306、psutil 5.9.8。Frida 和 pywin32 现已作为 Windows 依赖加入项目。

先启动对应 QMT，然后从项目目录执行：

```powershell
python tools/qmt_component_login.py --binding 华泰模拟测试 --prompt
```

绑定名称必须与 `runtime/config/cfquant_web_config.json` 中的 `display_name` 精确一致。也可通过 `--config` 指定其他配置文件。

尚未登录时，工具始终读取调用方提供的密码并覆盖密码框内容。`--prompt` 从终端读取密码且不回显；没有该参数时从标准输入读取一行，便于调用程序通过管道传入。没有密码命令行参数，不应将密码写入命令文本。

可用 `--report <文件路径>` 保存不含密码和登录用户名的结果；`--timeout` 控制单次提交后的观察时长，默认 40 秒。工具退出码为 0 表示检测到登录主界面，其他结果为 1，运行环境或组件异常则停止并报错。

## 登录流程

1. 按绑定的安装目录精确匹配唯一进程，并用进程互斥锁阻止本工具并发提交。
2. 已经处于主界面时返回 `already_logged_in`，不再提交。
3. 登录中、需要验证码或已有网络错误提示时停止并报告。
4. 配置了登录账号时，清空账号和密码，重新设置该账号；账号相同也执行覆盖。不读取客户端记住的密码。
5. 取得调用方提供的密码后调用 `QLineEdit::setText()` 覆盖密码框，再调用 `CLoginDialog::slot_loginClicked()`。网页自动登录从加密存储读取绑定密码。
6. 最多提交一次，密码被拒绝时停止。未提供密码时返回需要密码，不尝试客户端记住的值。
7. 网络异常、超时、验证码或未知提示不触发第二次登录。
8. 仅在目标进程出现对应登录用户名的 Qt 主窗口时报告本次登录成功。不会把调用登录方法本身当作成功。

登录用户名与绑定资金账号可能不同。配置了登录账号时，工具使用配置值；独立命令行工具未配置该值时使用当前选中用户。读取用户名仅用于内存中的主窗口匹配，操作期间发生其他账号切换则停止。该判断确认客户端登录界面已完成，不代替逐个交易账户的连接、权限或行情可用性检查。

## 实现与边界

`cfquant/qmt_component_agent.js` 经 Frida 临时加载到选定进程，定位 Qt 对话框和密码控件，并将调用安排到目标 GUI 线程。结束后解除附加，不修改磁盘上的 QMT 模块。

不依赖前台焦点，但客户端自身可能在登录完成后激活窗口。窗口最小化已经验证；锁屏、远程桌面断开、没有物理显示器、开机无人登录 Windows 或服务 Session 0 场景尚未实测，不能由本次结果推断这些环境全部可用。

依赖内部导出方法和 Qt 对象布局，当前支持范围是上述两个版本，不能据此承诺任意券商、任意 QMT 版本只换密码都可用。

策略分支测试：

```powershell
python -m pytest cfquant/tests/test_qmt_component_login.py -q
```

测试涵盖覆盖已有密码、填入空密码框、账号相同仍覆盖、密码被拒绝后停止、已登录不重复提交，以及超时、网络问题、验证码、组件启动和登录进行中的状态处理。
